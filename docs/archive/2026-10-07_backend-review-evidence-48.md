### P2-102: 2026-10-03 那次把 `created_at` 改成可空的修正，**只改了 16 个同型字段里的 1 个** —— 余下 15 个仍声明为非空，而后端一律发 `null`
- **Scope / Evidence**: `docs/API.md` 与 `docs/API-zh-CN.md` 的**观测 wire 格式表**
  （约 `:1650-1686` / `:1613-1649`）。全库活体库 `mem_observations` **38,967 行**实测。
- **Problem**: 该表的 `Type` 列用 `\| null` 表示「可能为空」，**6 个字段已经这么标**
  （`refined_from_ids`、`generated_by_model`、`step_number`、`embedding_model_id`、`created_at`、
  `embedding_768/1024/1536`）。**另有 15 个字段的稀疏程度与之相当，却仍标成非空 `string` / `int` / `float` / `object`**：

  | 字段 | NULL 率 | 字段 | NULL 率 |
  |---|---|---|---|
  | `user_comment` / `last_accessed_at` | **100%** | `content_hash` | 48% |
  | `feedback_updated_at` / `feedback_type` / `quality_score` | 92% | `facts` / `files_read` / `files_modified` | 47% |
  | `subtitle` | 81% | `extractedData` | 46% |
  | `refined_at` | 79% | `source` | 35% |
  | | | `prompt_number` / `narrative` | 15% / 6% |

  **键从不缺失**——活体 `GET /api/observations` 每行恒为 **34 个键**，稀疏字段到达时是**显式 `null`**
  （三条连续样本逐键核对），所以「声明为非空」与实际行为正面冲突。
  **这是同一次修复只做了一半**：2026-10-03 的 changelog 行原文就是
  「**The type**: `created_at` was documented as a non-null `string`… It is now `string \| null`」，
  理由完全适用于同表另外 15 行，那次却只改了 `created_at` 一行。
- **为什么现在才逮到**：前几轮比的是**字段是否存在**（第 334 轮「字段↔活体对拍」），

  `access_count`、`created_at_epoch`），保持非空类型。
  `POST /api/memory/observations` 的**请求体**表也刻意不动——它自带 `Required` 列，可选性已在那里表达。

  `string` → `string \| null` **只增加可能性、不减少**，任何原本能处理 `string` 的客户端仍然成立，
  属向后兼容修正，不构成对外契约收窄。
